# Code conventions – S.U.C.K.-3000 / R.E.V.A.

Team: Los Pepos (group 213027_12) · Course: Programación para Videojuegos (213027A) · Stage 4

Project: Unity 6.6 (6000.6.6f1), Universal Render Pipeline (URP), Third Person Starter Assets.
Scripts live in `Assets/GameScripts`. Editor tools live in `Assets/Editor`.

## Rules we follow

- Create, move, rename and delete assets only inside the Unity Editor, so the `.meta` GUID is kept.
- Commit every asset together with its `.meta` file. Without it, Unity creates a new GUID on the next computer and scenes and prefabs lose the reference.
- Expose Inspector fields as `[SerializeField] private`, never `public`, and explain each one with a `[Tooltip]`.
- Use only URP shaders (URP/Lit, URP/Simple Lit, URP/Unlit). Built-in Standard materials render magenta.
- Do not switch the render pipeline: it invalidates every material.
- Scripts generated with AI start with the comment `// Generated by AI`.
- Commit messages are written in English.

## MonoBehaviour lifecycle

| Phase | We use it for |
|---|---|
| Awake | Find and cache references (for example the BackpackInventory in VacuumAbsorber) |
| OnEnable / OnDisable | Subscribe and unsubscribe events (BinCounterLabel listens to SortingBin) |
| Start | Wiring to other objects (SortingBin finds the BackpackInventory) |
| Update | Input and gameplay logic (Q to absorb, E to deposit) |

Rule: every subscription in OnEnable has its unsubscription in OnDisable.

## How scripts talk to each other

Scripts use C# events, so the interface updates without depending on the rest of the code.

| Event | Raised by | Meaning |
|---|---|---|
| OnWasteChanged | BackpackInventory | Amount of one waste type changed |
| OnSelectionChanged | BackpackInventory | Selected compartment changed |
| OnCountChanged | SortingBin | Deposited count of one bin changed |
| OnScoreChanged | SortingBin (static) | Points added |
| OnWasteDeposited | SortingBin (static) | An item was deposited |

## Scripts

| Script | Function |
|---|---|
| WasteItem | Marks each piece with its waste type |
| BackpackInventory | Stores and gives waste by type, handles the selection |
| VacuumAbsorber | Detects nearby waste, moves it to the nozzle and stores it |
| SortingBin | Accepts only its own type, adds points and counts |
| BinCounterLabel | Shows the count on the bin sign |

Editor tools (menu Tools > S.U.C.K.-3000): Build Vacuum Prop and Setup Waste.

## Controls (all rebindable in the Inspector)

| Action | Keyboard | Gamepad |
|---|---|---|
| Absorb | Q | Y / Triangle |
| Deposit | E (also automatic near the bin) | X |
| Choose compartment | 1 to 5, mouse wheel | LB / RB |

## Before every commit

1. The project compiles with zero errors in the Console.
2. The full loop works: absorb, deposit and see the counter go up.
3. The diff in GitHub Desktop shows only the changes you meant to make.
